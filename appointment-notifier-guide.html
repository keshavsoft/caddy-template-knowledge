How to Inspect appointment-notifier & Determine Its Caddy Configuration

The entire reason we built these tools is to publish real applications like appointment-notifier on your VPS. Here is the exact mental process of opening the code, deducing the port and protocol, choosing the right template, and going live.

🕵️ Phase 1: The 3-Minute Code Investigation

Before you run any CLI tool, you inspect the application itself. Open d:\KeshavSoftRepos\nov\8\appointment-notifier and examine three specific lines:

1

Inspect app.js: What port does the server listen on?

Look at lines 10-11 and 97 of app.js:

appointment-notifier/app.js (Lines 10-11, 97)
const HOST = process.env.HOST?.trim() || "127.0.0.1";
const PORT = Number(process.env.PORT ?? 3000);

server.listen(PORT, HOST, () => {
    console.log(`Appointment notifier listening on ${HOST}:${PORT}`);
});

Finding: The application listens on port 3000 (or whatever process.env.PORT is passed at runtime).

2

Inspect app.js: Does it use WebSockets? And on which port?

Look at lines 77 and 88-95 of app.js:

appointment-notifier/app.js (Lines 77, 88-95)
const wss = new WebSocketServer({ noServer: true });

server.on("upgrade", (req, socket, head) => {
    const pathname = new URL(req.url, "http://localhost").pathname;
    if (pathname !== "/ws") {
        socket.destroy();
        return;
    }
    wss.handleUpgrade(req, socket, head, (ws) => wss.emit("connection", ws, req));
});

Finding: Notice noServer: true and server.on("upgrade", ...). This is the classic Node.js pattern where the WebSocket server is attached directly to the existing HTTP server.

It does NOT create a second port. Both normal web pages (/doctor, /display) and WebSocket live streams (/ws) run on the single port 3000!

3

Inspect Frontend: How does the browser connect?

Look at lines 6-7 of public/v2/js/display.js (and doctor.js):

appointment-notifier/public/v2/js/display.js (Lines 6-7)
const wsProtocol = location.protocol === "https:" ? "wss:" : "ws:";
const socket = new WebSocket(`${wsProtocol}//${location.host}/ws?role=display`);

Finding: The browser dynamically inspects location.protocol and location.host. When deployed to https://appointment.keshavsoft.com/display, it automatically opens wss://appointment.keshavsoft.com/ws?role=display on the standard HTTPS port 443!

⚖️ Phase 2: Choosing the Template (Why proxy Wins)

Now let's compare our findings against the templates available in caddy-template:

Template When It Is Used Does It Fit appointment-notifier?
static Pure HTML/CSS files without any Node.js server. ❌ No. appointment-notifier has active server logic and WebSocket events.
ws-split Two separate server processes: Web server on Port A (e.g. 9011) and WebSocket daemon on Port B (e.g. 8080). ❌ No! appointment-notifier only has ONE port (3000). If you used ws-split, you would be routing traffic to a second phantom port!
proxy Single server process handling both HTTP web requests and WebSockets on one port. ✅ 100% Perfect Match! This is the exact architecture of appointment-notifier.
Why Caddy handles WebSockets on proxy with zero configuration:
Unlike Nginx or Apache, Caddy natively inspects incoming HTTP request headers. When a client requests an HTTP Upgrade (Upgrade: websocket), Caddy automatically converts the reverse proxy into a bidirectional streaming tunnel to localhost:3000. You don't need any special split rules!

⚡ Phase 3: The Exact CLI Command

Now that you know the target domain is appointment.keshavsoft.com and the local port is 3000, you run:

Terminal Command 
npx caddy-template proxy appointment.keshavsoft.com 3000

This generates the exact, schema-compliant Caddy JSON route block:

Generated Route JSON 
{
  "match": [

      "host": [

  "handle": [

🚀 Phase 4: Going Live on VPS (103.174.102.116)

Here are the 4 final steps to expose appointment-notifier to the world:

1

GoDaddy DNS: Add Subdomain A-Record

In your GoDaddy DNS manager for keshavsoft.com, add an A Record:

  • Type: A
  • Name: appointment
  • Value / IP: 103.174.102.116
  • TTL: 1/2 Hour (or default)
2

VPS: Pull & Start with PM2 on Port 3000

On your VPS (103.174.102.116):

SSH / VPS Terminal
cd /var/www
git clone https://github.com/keshavsoft/appointment-notifier.git
cd appointment-notifier
npm install --production

# Start with PM2 on Port 3000
PORT=3000 pm2 start app.js --name appointment-notifier
pm2 save
3

Caddy: Insert Route & Reload

Open /etc/caddy/caddy.json, append the generated route block into apps.http.servers.srv0.routes, and reload:

SSH / VPS Terminal
caddy reload --config /etc/caddy/caddy.json
4

Live Verification!

Open your browser and test:

  • Doctor Portal: https://appointment.keshavsoft.com/doctor
  • Display Board: https://appointment.keshavsoft.com/display
  • Reception Desk: https://appointment.keshavsoft.com/reception

Click "Enable Voice" on the Display screen, call Token 101 from the Doctor screen, and hear the real-time text-to-speech announcement over secure WSS!
